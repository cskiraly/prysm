### Added

- `notes/rowdas`: check in the RowDAS (EIP-8371) plan, design doc, measurement plan and experiment schedule, plus a handoff document.
- `config/params`: `ROW_SUBNET_COUNT`, the number of RowDAS row subnets. A config value rather than a constant, because with one row subnet per node a small network leaves nodes alone on their row subnet and cannot exercise the feature.
- `beacon-chain/core/peerdas`: row subnet assignments — the static node-to-subnet map and the per-slot blob-to-subnet permutation, with its exact inverse so a node can tell which blobs its row subnet carries.
- `proto/prysm/v1alpha1`: `PartialDataRowSidecar`, the RowDAS row wire message — the transpose of `PartialDataColumnSidecar`, with a bitmap over columns instead of blobs and the same header container.
- `consensus-types/blocks`: `PartialDataRow`, the in-memory row exchanged on the row topics, sharing the block's partial-message group id with its columns so one validated-header cache serves both.

- `beacon-chain/core/peerdas`: `RecoverRow` recovers one row's missing cells and proofs from the half it holds — the per-blob unit of work RowDAS distributes.

- `beacon-chain/p2p/partialdatacolumnbroadcaster`: serve RowDAS row topics from the same broadcaster and the same gossipsub partial-messages extension as the columns — topic classification by axis, row state per (topic, group), header validation and caching shared with the column path, and `PublishRow`/`RowSnapshot` for the reconstruction duties.

- `beacon-chain/p2p/partialdatacolumnbroadcaster`: the cross-fill bridge — a cell verified on one DAS axis is offered to the other, so a cell learned on a row topic fills a custodied column without any column-topic traffic, and a cell from a column topic advances the row towards its reconstruction threshold.

- `testing/gossipsim`: a multi-node gossipsub harness over simlibp2p — topology generators, per-node link and latency models, a production-matching pubsub configuration, and a raw tracer that accounts for every byte on the wire. Promoted unchanged from the payload-segmentation study so two studies share one substrate.

- `beacon-chain/p2p/rowintegrationtest`: the RowDAS measurement harness — N nodes running the real broadcaster over real gossipsub with real KZG — plus the first three experiment results (R3 duplication, R4 pooled-custody coverage and reconstruction).

- `beacon-chain/p2p`: the `data_row_{subnet_id}` gossip topics — topic name and format, allow-list registration from Fulu, scoring parameters, and `RequestPartialMessages` on join. Deliberately absent from `gossipTopicMappings`: row topics carry no full messages.
- `beacon-chain/p2p`: `filterPeerForDataRowsSubnet` finds peers by row subnet, computed from the node ID alone — no ENR entry and no MetaData field, so a peer cannot misreport its subnet.
- `beacon-chain/sync`: subscribe to this node's single row subnet, with a validator that rejects any full message arriving on a row topic.
- `beacon-chain/sync`: the RowDAS reconstruction duties — three phases (own row, other rows, opportunistic) with bounded delays expressed as fractions of a slot, cancelled when the row completes by other means.
- `cmd/beacon-chain`: `--row-das`, refused at startup without `--partial-data-columns` or with `ROW_SUBNET_COUNT=0`.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: `CrossForwardRow` pushes a recovered row's cells into the column subnets this node does not custody, one single-cell partial column per topic. The mechanism only — which columns, how many and when are the caller's, which is where EIP-8371 leaves them.
- `beacon-chain/sync`: cross-forward a row after recovering it. A pushed column explicitly requests nothing: asking a subnet we do not custody for cells is the pull direction, which is a separate arm.
- `third_party/go-libp2p-pubsub`: `Topic.SetPartialInterest` announces that we request partial messages on a topic we joined but did not subscribe to. Sent as `subscribe=false` with the partial flags set, so no new protobuf field is needed and an implementation that does not know about it reads a plain unsubscribe. Such peers are tracked in a map of their own, not as a flag inside `peerTopicState`, so they cannot leak into mesh selection, gossip targets or full-message forwarding; `MeshPeers` gains a second pass over it, which is the only place they can be reached.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: `PullRowFromColumns` asks the column subnets this node does not custody for the one cell each holds of a row — EIP-8371's optional pull direction. The request names exactly that cell, not the whole column.
- `cmd/beacon-chain`: `--row-das-pull`, off by default and refused without `--row-das`.

- `beacon-chain/p2p/rowintegrationtest`: R12 — whether the row axis substitutes for a node's *own* dead column path, as opposed to loss at the source. It does, bounded by `rows_subscribed / blob_count`: a node whose column subnets deliver nothing recovers all of its columns at 1 blob and none at 4, because its one row subscription carries one of the four cells each column needs. So RowDAS's resilience is network-level rather than node-level, and per-node path diversity would need nodes on many row subnets.
- `beacon-chain/p2p/rowintegrationtest`: R11 — how much column-path loss the row axis absorbs. Sweeping the number of column subnets still delivering data, with nodes holding 8 of 128 columns each: every lost column is recovered while 64 or more survive, none once 63 do. The boundary is the erasure-coding threshold to the column, so RowDAS does not add a margin — it makes an existing one reachable by nodes that individually cannot reconstruct, where PeerDAS rescues nothing anywhere on the sweep.
- `beacon-chain/p2p/rowintegrationtest`: R5 and R6, the two adversarial arms. R5 — a proposer withholding a single cell of one row: **zero** recoveries are scheduled anywhere, because the row axis triggers on cells in hand rather than on custody, where PeerDAS burns one futile attempt per qualifying node per slot. The cost it turns up is that the subnet still pools the row for 98% of a successful row's bytes, with the stopping condition sitting unread in the availability bitmaps. R6 — every member of a row subnet refusing to serve: column completion 691 ms against 689 ms with no row subnet at all, so a suppressed subnet degrades to the status quo rather than to something worse, which is the band the EIP claims.
- `beacon-chain/p2p/rowintegrationtest`: R2 — column completion under row traffic, across three arms and a seed sweep. The row axis roughly doubles total partial bytes and makes column completion 22% faster at the median, via path diversity rather than reduced work.
- `beacon-chain/p2p/rowintegrationtest`: R1 — the reconstruction-work claim, split into the mapping (duty and occupancy, analytic) and the race (does the phase-1 jitter actually turn k candidate recoveries into one). Plus `TestRecoveredRowCellsVerify`, which pins that a recovered row's cells and proofs verify and match the original.
- `beacon-chain/p2p/rowintegrationtest`: the column axis — column subnets alongside the row subnet, custody-driven subscriptions, a withholding proposer, and per-column-subnet mesh settling — plus R9, the cross-forwarding arm comparison it exists for.
- `testing/gossipsim`: `RecordingTracer.MeshPeersInTopic` and `AwaitTopicMesh`, so a multi-topic experiment can assert that *this* topic's mesh has formed. `MeshPeers` counts distinct peers across all topics and saturates at the connectivity degree, which makes a per-topic precondition unassertable.

### Fixed
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: seed a row from the columns the node already holds. `crossFillRowFromColumn` was reachable only from the incoming path, so cells a node supplied itself — a proposer publishing its columns, a column rebuilt locally, one from the execution client — never entered its row state. Measured: with the proposer also custodying columns, every node stalled at 56 of the 64 cells the reconstruction threshold needs, and the node holding all 128 columns was the one unable to serve the row axis. The mirror of a bug already fixed in the other direction.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`, `beacon-chain/sync`: cancel a pending row recovery on a peer's availability rather than on local completion. The phases waited for the row to complete locally, which takes 783 ms against a 600 ms window — and once a node stops fetching a row it can already recover, never at all: 0 of 15 peers against 15 of 15 before. A node that recovers a row announces every cell of it, and that observation lands in one round trip (188 ms median). Measured on 16 reconstructors sharing a subnet, recoveries at the shipped window fall from **16 of 16 to 5 of 16**, and the window gains a knee instead of a flat line. Both halves are required — the claim is unverified, so it only fires when this node also wants nothing further, which a peer that cannot serve what it claims could not have arranged — and because that proof is partial, the recovery is demoted to phase 3 rather than dropped: a liar costs the delay, not the row.
- `consensus-types/blocks`, `beacon-chain/sync`: a row participant no longer asks for every cell it lacks. That is the column axis's rule, and it is right there — a node subscribed to a column stores every cell it asks for. A node does not store a row; it stores the cells of its own columns. So: while short of the reconstruction threshold it asks for everything missing, because any cell brings it closer and it cannot know which ones its peers hold; once it can recover the row it asks only for the cells of columns it keeps. A node whose custody already covers the threshold therefore asks for nothing beyond its own columns, which is what EIP-8371 says such a node needs. Measured on one binary with the same seeds: **row-axis bytes down 32%** at 24 nodes and **1.8–2.5x** under withholding, for a column-completion gain of 16% instead of 22%.
- `beacon-chain/sync`: attach RowDAS reconstruction duties to at most one block root per slot, as EIP-8371 requires. Duties were keyed by group id, i.e. by block root, so a proposer publishing k blocks for one slot multiplied every affected reconstructor's work by k — a cheap amplification vector against the one CPU cost RowDAS exists to reduce. First valid root seen wins where roots are recorded; the head-branch clause is evaluated lazily, when a duty for a competing root would be declined, because gossip validation runs before block processing and nothing is canonical yet at the moment a root arrives.
- `beacon-chain/sync`: measure the reconstruction phase delays from block-root acquisition, not from the moment the row became recoverable. The EIP's reference is shared across nodes, which is what makes phase 2 a fallback for phase 1 having failed; the per-node one drifts with the thing it backs up. The time spent reaching the threshold is now spent out of the phase window rather than added to it, and `beacon_row_reconstruction_scheduling_lag_seconds` reports how much of each window that was.
- `consensus-types/blocks`: de-conflict partial-message requests. A node's `requests` bitmap was everything it lacked and the same bitmap went to every mesh peer, so each peer independently served the whole gap — received bytes linear in mesh degree with a coefficient of one. Requests are now assigned: each missing part is asked of one peer that holds it, tracked in a per-part claim ledger with a size-scaled timeout, and a lapsed claim prefers a peer not already asked. Measured **8.6x fewer bytes** at mesh degree 8, and the cost no longer scales with degree (1.08x/1.12x/1.16x against 5.16x/9.61x/13.90x).
- `beacon-chain/p2p`: `TestPeer_Disconnect` uses an ephemeral port. It hardcoded 5000/5001, so anything already bound — a docker-proxy on 5001 is enough — failed it.
- `beacon-chain/p2p/rowintegrationtest`: `awaitRecoverable` waits for a stall rather than one unchanged poll. One unchanged poll cannot tell "not started" from "done", and an exchange whose first threshold landed after 200 ms returned zero and read as total failure.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: build column state from the group's cached header when a metadata-only RPC arrives. `headerSentCache` is keyed by group, so a proposer's second and later eager pushes to the same peer carry no header — and the receiver's state-creation path required one, so a peer custodying k columns received partial cells on exactly one of them per block. Measured: seven peers, 1 of 8 columns each. Masked in production by the full-message broadcast, so the symptom was a silent loss of the early-cell optimisation.

- `testing/gossipsim`: restore the mesh-settlement semantics the promotion changed — `AwaitMesh` waits until every node is inside the `Dlo..Dhi` band and fails on timeout, rather than returning when the aggregate mesh total stops changing.
- `beacon-chain/p2p/segmentintegrationtest`: `gossipDhi` honours `SEGMENT_MESH_D` again, `SEGMENT_IDONTWANT_THRESHOLD=0` means zero rather than "production", the pubsub option order is back to production/caller/environment, and the background topic keeps its original name.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: check both row parts-metadata bitmaps, not just `available` — a wrong-length `requests` poisoned that peer's state for the lifetime of the group. Malformed row messages are now downscored rather than returning an unscored error.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: cross-fill a published row into the columns we custody. The incoming path only cross-fills cells that arrived as a message, so a node could recover a row, serve it to its peers, and still be missing the cells for its own columns.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: `PublishRow` clones on ingress; it previously adopted the caller's slices as loop-owned state.
- `beacon-chain/p2p/partialdatacolumnbroadcaster`: refuse row topics on a Gloas fork digest, where the Fulu group id form would break cross-fill silently.
- `beacon-chain/p2p/rowintegrationtest`: R3's degree sweep now sets the gossipsub mesh degree, not only the connectivity graph, and records the mesh that actually formed.
- `third_party/go-libp2p-pubsub`: drop a topic's peer-initiated group counter along with the last group state under it; both maps are keyed by a peer-controlled topic string, so the counter leaked one entry per topic for the process lifetime.

### Changed

- `beacon-chain/p2p/segmentintegrationtest`: consume `testing/gossipsim` rather than carrying the harness itself. Every `SEGMENT_*` variable, the segment size and the phase options stay here; the builder no longer reads the environment.
- `beacon-chain/core/peerdas`: `VerifyDataColumnsCellsKZGProofs` now delegates to `VerifyCellsKZGProofs`, named for what it does: both DAS axes reduce to batch-verifying (commitment, cell index, cell, proof) bundles, so the row axis needs no verifier of its own.
- `consensus-types/blocks`: `NewPartialDataRow` refuses a wrong-length KZG commitments inclusion proof, since the header container cannot encode one and a row always has a header to send — the failure now names the caller instead of surfacing at publish time.
- `consensus-types/blocks`: share the per-peer partial-message publish state machine between columns and rows behind a `partialParts` interface, rather than keeping a second copy of it.
- `beacon-chain/core/peerdas`: derive the custody-group hash through a shared helper, so the domain separation between custody (hash bytes 0:8) and row subnets (bytes 8:16) is visible in one place.
